### 1. alibaba/open-code-review ⭐ 38,609

- 🔗 https://github.com/alibaba/open-code-review
- 语言：Go
- 本周新增：15,504 stars

**项目简介**

阿里开源的混合架构代码评审工具，结合确定性规则流水线和 LLM Agent。它强调安全、速度和工程可落地性，内置多语言规则集，覆盖 NPE、线程安全、XSS、SQL 注入等常见问题，并兼容 OpenAI 与 Anthropic。

**核心特性**

- **规则 + LLM Agent 混合评审**：确定性规则负责稳定问题识别，LLM Agent 负责上下文理解和解释。
- **行级评论**：评审结果可以定位到具体代码行，适合接入 PR 工作流。
- **多语言规则集**：内置常见工程风险规则，不只依赖大模型自由发挥。
- **企业级实践背景**：项目描述强调经过阿里规模验证，关注性能和可靠性。

**为何爆火**

代码评审是 AI 编码落地里最刚需、也最容易暴露风险的环节。单纯让 LLM 读 diff 容易不稳定，而 `open-code-review` 用规则系统兜底，再让 LLM 补足语义理解，方向更接近真实工程团队可接受的方案。

### 8. mksglu/context-mode ⭐ 23,799

- 🔗 https://github.com/mksglu/context-mode
- 语言：TypeScript
- 本周新增：1,242 stars

**项目简介**

面向 AI 编码 Agent 的上下文窗口优化工具。它通过沙箱化工具输出、持久化会话记忆，以及 MCP + hooks 路由机制，降低上下文浪费。

**核心特性**

- **工具输出压缩**：项目描述给出 98% output reduction，目标是减少无效上下文。
- **会话记忆持久化**：让 Agent 不必每轮从零开始。
- **MCP + hooks 路由**：把不同平台和能力接入统一的执行路径。
- **面向编码 Agent**：直接服务于当前最活跃的 AI 编码场景。

**为何爆火**

上下文窗口是 Agent 的核心瓶颈。模型再强，如果上下文被日志、无关输出和重复信息占满，执行质量就会下降。`context-mode` 针对的是 Agent 工程化里的真实成本点。

## 📈 深度趋势分析

### 趋势一：AI 编码的中心从“模型能力”转向“工作流能力”

`Claude Code`、`Cline` 这类工具已经证明 Agent 可以执行开发任务。现在新增热度集中在 `open-code-review`、`agent-skills`、`context-mode`、`worktrunk`、`orca` 这些工作流基础设施上，说明开发者关注点正在从“模型能不能写代码”转向“它能不能稳定地参与真实工程流程”。

### 趋势二：上下文、记忆和技能成为 Agent 的第二层能力

`ECC`、`agent-skills`、`context-mode`、`Agent-Reach` 都在解决同一类问题：让 Agent 获得更好的上下文、更稳定的流程和更明确的能力边界。长期看，优秀 Agent 系统的差异不会只来自模型，也会来自这些外围能力。

### 趋势三：知识库正在从 RAG Demo 走向持续维护系统

`WeKnora` 和 `knowledge-work-plugins` 的热度说明知识工作正在成为 Agent 的重要战场。单次问答价值有限，真正有价值的是把文档、搜索、推理、沉淀和更新串成闭环。

### 趋势四：并行 Agent 会倒逼 Git 和工作区工具升级

当一个开发者可以同时让多个 Agent 跑任务，传统单工作区开发方式会遇到冲突、上下文污染和切换成本问题。`worktrunk`、`orca` 这类项目说明“多 Agent 协作基础设施”会成为新的工具层。

### 趋势五：内容生产会越来越像软件工程

`hyperframes` 用 HTML 描述视频，`markitdown` 把文件转成 Markdown，`gods-eye-view` 用 Web 技术组织真实空间数据。这些项目共同指向一个方向：内容生产不再只是编辑器里的手工操作，而是可以被结构化、版本化、自动化的工程流程。
