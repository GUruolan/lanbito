### 2. chopratejas/headroom ⭐ 40,288

- 🔗 https://github.com/chopratejas/headroom
- 语言：Python

**项目简介**

在内容到达 LLM 之前对工具输出、日志、文件和 RAG chunk 进行智能压缩——减少 60-95% 的 token 消耗，同时答案质量不变。提供 Python 库、代理和 MCP 服务器三种接入方式。

**核心特性**

- 🗜 **智能语义压缩**：保留关键语义信息的同时大幅削减 token 数量
- 📉 **60-95% token 节省**：显著降低 OpenAI/Anthropic 等 API 调用成本
- 🔌 **MCP 服务器支持**：可作为 Model Context Protocol 服务器，接入任意兼容客户端
- 🧩 **三种接入方式**：Python 库（轻量集成）、代理模式（透明转发）、MCP Server（标准协议）
- 📊 **质量不降低**：压缩算法保证 LLM 输出效果与原始内容相当

**适用场景**：高日志量的 AI 运维分析、RAG 系统 token 预算控制、长文档处理成本优化

**为何爆火**：token 成本是 LLM 应用最核心的运营成本之一，headroom 以"先压缩再处理"切入，开辟了 LLM 成本优化的新赛道，连续多周强势在榜。

### 6. n0-computer/iroh ⭐ 10,310

- 🔗 https://github.com/n0-computer/iroh
- 语言：Rust

**项目简介**

IP 地址会变化，但 dial key 不会。iroh 是一个 Rust 编写的模块化网络协议栈，让设备间直连更加稳定可靠，不依赖传统 IP 地址。

**核心特性**

- 🔑 **Dial Key 寻址**：基于密钥而非 IP 地址，NAT 穿透友好
- 🧩 **模块化设计**：按需组合网络协议组件，轻量且灵活
- 🦀 **Rust 原生**：内存安全、高性能，适合系统级网络应用
- 🔄 **直连优先**：P2P 直连，无中心服务器依赖
- 📡 **低延迟**：优化的传输协议栈，延迟显著低于传统方案

**适用场景**：P2P 应用、分布式系统网络层、IoT 设备互联、去中心化通信

**为何爆火**：在 IPv4 地址枯竭、NAT 遍地的网络环境下，传统 IP 寻址越来越不可靠。iroh 以"key-based 寻址"替代 IP，直击 P2P 和分布式系统的核心痛点，Rust 实现更添可靠性光环。
